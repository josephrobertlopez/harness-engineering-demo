## `2231616` — Implement WikiSkill: gated skill evolution over a compounding wiki

- **date:** 2026-09-23
- **author:** Joseph Lopez
- **sha:** `223161696eade92b87a7c460d5eeecb3d46df709`

Working implementation of arXiv 2608.27454 -- three persistent layers (raw
traces, wiki patterns, executable skills) driven by an evolution loop that
accepts a skill change only when it improves a held-out validation split.

Runs end to end offline on a bundled 20-task benchmark: validation climbs
0.00 -> 1.00 in six iterations with a genuine rejection and rollback at
iteration 3, and held-out test goes 0.000 -> 1.000 against the no-skills
baseline.

Structural guarantees, rather than conventions:
- The Inference Agent has no wiki handle and its module does not import the
  wiki layer. This is the paper's load-bearing ablation (63.7% -> 60.9% when
  inference can read the wiki), so it is enforced by signature and asserted
  by test.
- The wiki has no delete path, so rollback cannot reach it. Patch batches are
  all-or-nothing, because a half-applied batch on a never-rolled-back layer
  is permanent damage.
- Skill sets are immutable and content-addressed behind an atomic HEAD
  pointer. Rejecting a proposal is "never move HEAD", so there is no undo
  path to get wrong.
- Decide, journal, then act: the only irreversible step runs strictly after
  the decision justifying it is durable, which is what makes resume exact.

Two deliberate deviations from the paper, both documented in the README: the
gate re-measures the incumbent in the same batch as the candidate rather than
comparing against a stale R_best (sampling cannot be pinned -- temperature is
removed on Opus 5 and Sonnet 5 -- and accepted noise compounds into the
lineage); and the ReAct loops use a parsed text protocol rather than native
tool-use blocks, so one code path serves all three backends.

Stdlib-only on Python 3.12+; 73 tests run offline with no install and no key.

## `e6d4d57` — Run rollouts in parallel, and record the first live result

- **date:** 2026-09-23
- **author:** Joseph Lopez
- **sha:** `e6d4d574d2f4e937fb17882d756fb49791f3cf4e`

Rollouts were sequential, so one iteration was ~20 subprocess calls at
20-45s each: 10-15 minutes, which gated every experiment downstream. They
are independent by construction -- a fresh environment per task, a separate
trace file per task, a content-addressed response cache with atomic writes
-- so a thread pool is close to linear speedup.

Results are collected into task order rather than completion order, because
the scores and the maintainer's stratified sample must not depend on which
rollout happened to finish first. Cached rollouts resolve on the calling
thread before the pool starts, so the pool only does work that calls a
model. The two pieces of genuinely shared state, the cache hit counters and
the CLI cost accumulator, now hold a lock.

Speed is worthless if it changes the answer, so tests/test_concurrency.py
asserts that parallel and sequential produce identical traces in identical
order, an identical workspace over a full run, exactly one trace per task,
and that cached rollouts are not re-run. The mock suite also got faster
(70s -> 47s).

First live result on the bundled benchmark, now in the README: held-out test
0.400 -> 1.000 with Haiku 4.5 inferring, Sonnet 5 maintaining, Opus 5
proposing. Documented alongside the two caveats that matter -- five test
tasks, and convergence in a single iteration means this shows that a skill
helps, not yet that knowledge compounds across iterations.

## `67e9c80` — Turn the repo into a teaching monorepo

- **sha:** `67e9c8001af2d56d4fb2595d88a40b5ce7caf606`

Adds five tutorial tracks, a tool-neutral persona system, and the docs set
needed to hand this to a teammate as a zip. The organising idea is that the
harness is already an evaluation engine, so the tutorials do not describe
good practice -- they grade it.

Two enablers made that possible. `eval --skills-dir` scores an arbitrary
folder of hand-written skills, which is what turns "did the skill you wrote
help?" into a fact rather than an opinion. And `tutorials/check.py`
discovers exercises by convention and runs their checks offline.

The mock backend now recognises a rule stated in prose, not only the
internal marker, so a human-written skill can be graded with no API key. It
is keyword matching standing in for comprehension -- documented as such,
because it separates a specific instruction from a vague one but cannot tell
a well-written skill from a merely correct one.

Tracks: 00-prompting and 30-skill-authoring are graded, with four exercises
and reference solutions. 10-spec-driven (BMAD), 20-knowledge (LLM Wiki) and
40-harness are guided -- they need a live agent, so there is nothing
honest to check offline.

Personas are one neutral source per role, generated into Claude Code
subagents, Claude Code skills, human cards, and a portable JSON file.
Nothing tool-specific appears in the source, and `export.py --check` fails
on drift, so the four surfaces cannot diverge.

Three bugs fixed along the way, all found by running things rather than
reading them:

- Exercise discovery raised on a malformed check.py, taking down discovery
  of every other exercise. A broken exercise is now one failing exercise.
- The link checker flagged illustrative links inside code examples. It now
  strips fences and inline code first -- a checker that cries wolf is one
  people learn to ignore.
- `os.replace` intermittently failed with "Access is denied" on Windows when
  an antivirus or indexer held a handle on the destination. Atomic writes
  retry with backoff; each attempt is still a single rename, so atomicity is
  unchanged.

Verification of the generated tutorial content found three invented LLM Wiki

## `1294dff` — Add the thesis, and trace the pattern back to where it came from

- **date:** 2026-09-23
- **author:** Joseph Lopez
- **sha:** `1294dff90357b1a617a2dee2f9eaad7993be6bc4`

The repo now leads with a claim -- knowledge compounds when the thing you
edit and the thing you read are different objects -- but nothing stated the
argument or said where it came from. It reads as though the pattern were
noticed here. It was not.

Niklas Luhmann worked it out in the 1950s with a box of index cards: capture
is fleeting, literature notes are written in your own words rather than
pasted, permanent notes are atomic and linked, and structure emerges from
those links instead of being imposed. Tiago Forte rebuilt it for digital
tools as CODE, where Distill is a compile step producing a separate
artifact. Bryan Hogan's Obsidian walkthrough is the clearest short
demonstration of the principles working in a real tool -- the method is
Luhmann's and he says so, which is why it is cited as a demonstration
rather than a source.

docs/THESIS.md traces the arrangement through all four systems and names
the two rules they share: never edit the source, never hand-maintain the
derived thing. Both exist to prevent one failure -- a file that is
simultaneously the evidence and the conclusion, which you can neither
revise without losing its basis nor regenerate without losing your
thinking.

It also separates, explicitly, what this repo measures from what it merely
argues. Measured: a gated skill set took a held-out split from 0.400 to
1.000. Argued: that knowledge compounds across iterations, which rests on
four systems agreeing and one paper's ablations, and which the bundled
benchmark cannot yet demonstrate because it converges in a single
iteration. A tidy argument should not be allowed to imply a result it has
not earned.

All sources cited with links and authors.
